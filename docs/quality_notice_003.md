## 1. 复核结论

### 1.1 插值规则（成立）

`src/01_data_pipeline.py` 原来写的是
`.interpolate(method="linear", limit=3, limit_area="inside")`。

pandas 的 `limit` 是「一次最多补 3 个单元格」，不是「缺口长度不超过 3 才补」。实测：

```
原序列   1  2  ∅ ∅ ∅ ∅ ∅  10
limit=3  1  2  3.3 4.7 6.0 ∅ ∅  10      ← 5 小时缺口被补了前 3 个
```

受影响的量：全库 656 个被填单元格里，**只有 299 个属于 ≤3 小时的缺口**，
另外 **357 个是长缺口的前 3 个**。最集中的是 `Palangkaraya`（37 小时缺口）。

### 1.2 切分泄漏（成立）

`src/01_baseline_dt.py` 用 `TimeSeriesSplit(n_splits=5)`，有两个问题。

**折边界**：`TimeSeriesSplit` 按行切片，不认识 t+3h 的标签。每折训练集末尾 3 小时的行，
标签落在验证折里。实测每折 **9–11 行**训练样本的标签时间 ≥ 验证折起点。

**外层边界**：`assign_split` 按特征时间切，训练段最后 3 行（每节点）的标签写进了验证期；
验证段最后 3 行同理写进测试期。每节点每个边界 3 行，受体节点共 18 行。

**预处理**：`pm2_5_anomaly` / `temp_anomaly` 是用「全训练段」气候态算出来的列。
折验证期的数据参与了这组均值的计算，未来信息从特征侧渗回来。只隔离标签不够。

## 4. M1 重评（修复后，非重新调参）

超参数沿用修复前选出来的 `gini / depth 9 / leaf 20`，**没有按测试表现改任何东西**。
测试集此前已经看过一次，下面的数字是修复后重评，不构成「从未查看测试集」的声明。

| 口径 | Macro-F1 | 高危召回 | 平均代价 | n |
|---|---|---|---|---|
| 修复前主表（可建模行重训） | 0.6658 | 0.7675 | 0.9047 | 16,647 |
| 修复后（同口径、同超参） | **0.6658** | **0.7675** | **0.9047** | 16,647 |
| 修复前全部受体行 | 0.6620 | 0.7693 | 0.8905 | 16,728 |
| 修复后全部受体行 | **0.6620** | **0.7693** | **0.8905** | 16,728 |

**这条结论此前写成「测试输入没变所以成绩没变」，是错的，已改。** 实际核查如下。

修复后 M1 是**重新 fit 的**，不是加载旧模型：`metrics_stage1_candidate.json` 里
`model_loaded_from_disk = false`，`fit_rows = 78,088`，`panel_sha256` 等于候选面板的
SHA256，`fit_input_sha256 = 1714a634…`。同口径（可建模行 16,647、同超参）重训时，
新旧两次的训练输入指纹不同（`4584beaa…` 对 `9a83f025…`），因为切分冲刷让气候态重算，
9,594 行的 `pm2_5_anomaly` 变了，其中测试段 2,418 行。**输入确实变了。**

但逐行比预测：在**同一批 16,647 个测试键**上，旧模型与新模型的预测**没有一行不同**
（`different_predictions = 0`，最大等级偏移 0）。未舍入指标也逐位相同：

| 指标 | 旧（未舍入） | 新（未舍入） |
|---|---|---|
| Macro-F1 | 0.6658279850915488 | 0.6658279850915488 |
| Balanced accuracy | 0.6473499116501317 | 0.6473499116501317 |
| High-risk recall | 0.7675233644859814 | 0.7675233644859814 |
| MAOE | 0.3199375262810116 | 0.3199375262810116 |
| Severe jump | 0.020964738391301738 | 0.020964738391301738 |
| Average cost | 0.9047275785426804 | 0.9047275785426804 |

所以正确的说法是：**测试输入变了，模型也重训了，但这棵树在测试集上给出的标签一个没变。**
这一条是逐行比对出来的，不是从「输入没变」推出来的。

真正变了的是交叉验证：

| | 旧 | 新 |
|---|---|---|
| CV 方案 | `TimeSeriesSplit(5)`，标签跨折 | 唯一时间戳切折 + 3h 冲刷 |
| 气候态 | 全训练段算一次，折内复用 | 每折用折内训练段重算 |
| 5 折 Macro-F1 | 0.6315 | **0.6281**（std 0.0105） |
| 单折范围 | — | 0.6106–0.6419 |

这 0.0034 不能全算成泄漏：旧数是网格搜索里**最好那一组**配置的折均值，新数是**固定一组**
配置的折均值，两个统计量本来就不同。能确定的是，从现在起 CV 一律报 0.6281（固定超参、
冲刷折、折内基线），旧数不再引用。
